. Object Management.
	- Other players see the object you are holding by knowledge of obj_def.
	- If the object is a GUO - game unique object (i.e. a secret rock), then it
	  is still represented by obj_def.  The only diff is how one gets ahold of 
	  a GUO.

	- How does one get ahold of a GUO? GUOs can be realized through interaction
	  with a machine.  Once realized,  they can be stored in a player inventory
	  or carried by the player through the views to another location, then 'stored'
	  in another machine.

	- How are GUO kept unique?
	  Game unique objects are stored in a seperate table from other objects.  This 
	  is a global database table.  This table  contains the location of that object.
	  Therefore, a GUO can have only one location.
	  - Updates to the GUO database must go through the game owner.  The game owner
	    always owns all GUOs.
	  - If a GUO is generated by a machine, then the database is checked to ensure
	    that this is the only instance of that object. (the state of the GUO was
		'not yet realized').

	  - If a player with GUOs in her inventory logs off, then all GUOs in that 
	    inventory are returned to their 'realized machine' location.  This does
		not require the original generating machines to be returned to an original
		state (this would be too complex to achieve).  The 'GUO-Realized' location
		could be the next-to-final state of the originating machine. Thus, only one
		machine can originate a given GUO. Care must be taken with respect to states
		of related machines.

	  - In general,  GUO are tracked by the game owner.  Missing GUOs or GUOs
	    that cannot be realized by their origination machine are placed into
		a GUO shelf somewhere within the game.
